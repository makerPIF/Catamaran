## A. 모터가 안 돈다

### "삐——" 소리만 나고 돌지 않는다

ESC가 아직 아밍되지 않았습니다.

1. 부팅 후 **3초간 중립 신호**를 기다립니다 (펌웨어가 자동으로 보냅니다)
2. 그래도 안 되면 ESC의 3D 모드 설정을 확인하세요 → [01-HARDWARE.md §7](01-HARDWARE.md#7-esc를-후진-가능하게-만들기)
3. ESC 기동음이 아예 없으면 **배터리 전원이 ESC에 들어가지 않은 것**입니다

### 시동(ARM)을 눌러도 아무 반응이 없다

| 확인 | 방법 |
|---|---|
| RC 아밍 스위치 | FS-i6의 CH6가 올라가 있어야 GCS에서 시동이 걸립니다 |
| 배터리 전압 | `10.2 V` 미만이면 시동이 거부됩니다 |
| 페일세이프 사유 | 상세 텔레메트리의 `페일세이프` 칸을 확인하세요 |

GCS 로그에 `RC 아밍 스위치(CH6)를 먼저 올리세요` 가 뜨면 그대로 하면 됩니다.

### 한쪽 모터만 안 돈다

1. ESC 신호선(흰색)이 GPIO25 / GPIO26에 제대로 꽂혀 있는지
2. 좌·우 ESC 펄스 값(`pl`, `pr`)이 GCS에 다르게 나오는지 — 같다면 배선, 다르다면 ESC·모터
3. 모터 3가닥 커넥터 중 하나가 빠졌는지

## B. 조종이 이상하다

### 전진만 되고 후진이 안 된다

**3D(양방향) 모드가 꺼져 있습니다.** 이것이 가장 흔한 문제입니다.

BLHeliSuite에서 `Motor Direction` 을 **`Bidirectional`** 로 바꾸세요.
→ [01-HARDWARE.md §7](01-HARDWARE.md#7-esc를-후진-가능하게-만들기)

### 한쪽 모터만 반대로 돈다

모터 3가닥 중 **아무 2가닥**을 서로 바꿔 끼우면 회전 방향이 뒤집힙니다.
또는 BLHeliSuite에서 `Bidirectional Reversed` 를 선택하세요.

### 배가 계속 한쪽으로 돈다

| 원인 | 해결 |
|---|---|
| 같은 방향 프로펠러 2개 | **CW 1개 + CCW 1개**를 좌우에 나눠 답니다 |
| 무게중심이 한쪽으로 치우침 | 배터리 위치를 옮겨 좌우 균형을 맞춥니다 |
| 한쪽 모터 출력 부족 | 추력을 따로 측정해 비교합니다 |

### 조향이 너무 민감하다 / 둔하다

펌웨어 상단의 `STEER_GAIN` 값을 조정하세요 (기본 `0.65`, 범위 `0.4~0.9`).
작게 하면 둔해지고, 크게 하면 민감해집니다.

### 스틱을 놓아도 모터가 떤다

중립 불감대가 부족합니다. `PULSE_DEAD` 를 `30` 에서 `40~50` 으로 올려 보세요.

## C. GCS에 연결이 안 된다

### 순서대로 확인하기

1. **노트북이 올바른 Wi-Fi에 붙었는가** — `대전중앙중학교` 가 맞는지
2. **브라우저에서 `http://192.168.8.20/health` 가 열리는가**
   - `{"ok":1,...}` 가 나오면 → 본체는 정상, GCS 설정 문제
   - 안 열리면 → 본체가 공유기에 못 붙은 것
3. **본체 시리얼 모니터(115200)** 에 `[WiFi] 연결됨 IP=...` 가 찍혔는가
4. **공유기 대역이 맞는가** — TP-Link 계열은 `192.168.0.x` 입니다.
   두 `.ino` 파일의 `LOCAL_IP` · `GATEWAY` 와 GCS의 IP 입력칸을 모두 바꿔야 합니다

### 연결은 되는데 바로 끊긴다

| 원인 | 해결 |
|---|---|
| IP 충돌 | 공유기 DHCP 범위를 `100~150` 으로 제한 → [03-NETWORK.md](03-NETWORK.md) |
| 전원 부족 | ESP32가 리셋되고 있습니다. [F장](#f-운항-중-멈춘다) 참조 |
| Wi-Fi 절전 | 펌웨어의 `WiFi.setSleep(false)` 가 들어 있는지 확인 |

### "신호 없음" 이 자주 뜬다

텔레메트리가 2초 이상 끊겼다는 뜻입니다. 거리를 줄이고 통신 등급을 확인하세요.
영상 해상도를 `320×240` 으로 낮추면 조종·텔레메트리에 돌아가는 대역폭이 늘어납니다.

## D. 영상이 안 나온다

### 전혀 안 나온다 — ⓐ XIAO ESP32S3 Sense

| 확인 | 방법 |
|---|---|
| **PSRAM 설정** | 도구 → PSRAM → **`OPI PSRAM`** 이어야 합니다. 가장 흔한 실수입니다 |
| 카메라 결합 | 확장 보드를 "딸깍" 소리가 날 때까지 끝까지 밀어 넣습니다 |
| 파티션 | `Huge APP (3MB No OTA/1MB SPIFFS)` |
| 직접 접속 | 브라우저에서 `http://192.168.8.30/stream` 을 열어 봅니다 |

### 전혀 안 나온다 — ⓑ ESP32-CAM AI-Thinker

| 확인 | 방법 |
|---|---|
| **전원** | 5V **2A 이상**을 직접. 3.3V 핀이나 USB-TTL의 5V만으로는 모자랍니다 |
| **보드 선택** | `AI Thinker ESP32-CAM` (다른 ESP32 보드로 고르면 핀맵이 틀립니다) |
| PSRAM | 도구 → PSRAM → `Enabled` |
| 리본 케이블 | 커넥터 걸쇠를 올리고 끝까지 밀어 넣은 뒤 다시 내립니다 |
| `IO0` | 운용 중에는 **아무 데도 연결되지 않아야** 합니다 |
| XCLK | 저가 클론이면 펌웨어의 `XCLK_HZ` 를 `10000000` 으로 낮춰 보세요 |

시리얼 모니터에 `[CAM] 초기화 실패 0x...` 가 찍히면 리본 케이블 또는 전원 문제입니다.

### "Brownout detector was triggered" 가 뜨며 계속 재부팅한다 (ESP32-CAM)

**전원이 모자랍니다.** 이 보드에서 압도적으로 흔한 증상입니다.

1. `5V`–`GND` 사이에 **470 µF 전해 커패시터**를 답니다 (극성 주의)
2. UBEC #2의 용량이 3 A 이상인지 확인
3. 전원선을 더 굵게, 더 짧게
4. USB-TTL 어댑터의 5V로 구동하지 말고 UBEC에서 직접 받습니다

펌웨어에 브라운아웃 감지기를 끄는 코드(`DISABLE_BROWNOUT`)가 들어 있지만,
이것은 증상을 가릴 뿐 **근본 해결이 아닙니다.** 전원을 먼저 고치세요.

### 업로드가 안 된다 (ESP32-CAM)

| 증상 | 해결 |
|---|---|
| `Failed to connect` | `IO0`–`GND` 연결 후 **`RESET` 버튼을 한 번** 누르고 업로드 |
| 업로드는 되는데 안 돌아감 | 업로드 후 `IO0`–`GND` 를 **분리**하고 `RESET` |
| 중간에 끊김 | Upload Speed를 `115200` → `57600` 으로 낮춤 |
| 포트가 안 보임 | USB-TTL 드라이버(CH340/CP2102) 설치 |
| TX/RX | 서로 **엇갈려** 연결합니다 (U0R↔TX, U0T↔RX) |

### 통달거리가 짧다 (ESP32-CAM)

기본은 PCB 패턴 안테나입니다. 보드 뒷면 IPEX 커넥터 옆 패드 3개 중
가운데 연결을 IPEX 쪽으로 옮기면 외장 안테나를 쓸 수 있습니다.

> [!WARNING]
> **안테나를 먼저 연결한 뒤 전원을 넣으세요.** 안테나 없이 송신하면 RF 출력단이 손상됩니다.

### 보드가 너무 뜨겁다 (ESP32-CAM)

스트리밍 중 발열이 큽니다. 알루미늄 방열판을 붙이고, 방수 인클로저 안에 넣는다면
금속면에 닿게 배치하세요. 해상도를 낮추면 발열도 줄어듭니다.

### 뚝뚝 끊긴다

1. 해상도를 `320×240`, 화질을 `저용량` 으로
2. 안테나 방향·높이 확인 → [03-NETWORK.md](03-NETWORK.md)
3. 공유기 채널을 한산한 곳으로 변경

### 화면이 뒤집혀 있다

`usv_cam_xiao.ino` 의 `s->set_vflip(s, 0);` 을 `1` 로 바꾸세요.
좌우 반전은 `set_hmirror` 입니다.

## E. 센서값이 이상하다

### 위성 수가 0에서 안 오른다

- **실내에서는 잡히지 않습니다.** 하늘이 트인 야외로 나가세요
- 처음 켤 때(콜드 스타트) 최대 5분 걸립니다
- GPS 안테나 위를 금속이나 손으로 덮지 마세요
- TX/RX가 서로 엇갈려 연결되었는지 확인 (GPS의 TX → ESP32의 GPIO16)

### Roll·Pitch가 계속 흔들린다

| 원인 | 해결 |
|---|---|
| 모터 진동 전달 | MPU6050 아래에 양면 폼테이프를 붙여 띄웁니다 |
| 프로펠러 불균형 | 프로펠러 밸런싱 |
| 필터 부족 | `setFilterBandwidth` 를 `21_HZ` 보다 더 낮춥니다 |

### Yaw가 계속 돌아간다 (드리프트)

자이로만으로 적분하므로 서서히 틀어지는 것이 정상입니다.
**0.6 m/s 이상으로 움직이면 GPS 침로로 자동 보정**됩니다.
정지 상태에서의 드리프트는 무시해도 됩니다.

### 전압 표시가 실제와 다르다

1. 멀티미터로 배터리 전압을 실측합니다
2. 펌웨어의 `VBAT_CAL` 에 `실측 ÷ 표시` 값을 넣습니다
3. 다시 업로드

예: 실측 12.4 V, 표시 12.0 V → `VBAT_CAL = 1.033`

## F. 운항 중 멈춘다

### 상세 텔레메트리의 `페일세이프` 칸을 먼저 보세요

| 사유 | 뜻 | 대응 |
|---|---|---|
| `GCS_LINK_LOST` | GCS 명령이 1.5초 끊김 | 거리를 줄이고 통신 등급 확인 |
| `BATTERY_CRITICAL` | 전압 10.2 V 미만 | 즉시 회수 · 충전 |
| `CAPSIZED` | 롤 70° 초과 | 배를 바로 세우고 재시동 |
| `RC_DISARM` | RC 아밍 스위치 내려감 | CH6를 올립니다 |

사유는 5초간 화면에 남습니다. 놓쳤다면 GCS 로그를 올려 보세요.

### 사유 없이 ESP32가 리셋된다

**전원 문제입니다.** 공유기와 카메라는 순간 소비전류가 크게 출렁입니다.

1. UBEC을 **두 개**로 나눴는지 확인 — ①ESP32계 ②공유기·카메라
2. **ESC의 BEC 빨간선을 뽑아 절연**했는지 확인 (두 ESC의 5V가 서로 싸웁니다)
3. UBEC 용량이 3 A 이상인지
4. 배선 굵기와 납땜 상태

→ [01-HARDWARE.md §5](01-HARDWARE.md#5-전원-계통)

### 운용 시간이 계산보다 훨씬 짧다

| 확인 | |
|---|---|
| 프로펠러가 규격에 맞는가 | **1045를 3S에 물리면 정격 초과**입니다 |
| 출력 제한을 몇 %로 쓰는가 | 전류는 스로틀의 **세제곱**에 비례합니다 |
| 배터리가 노후되었는가 | 셀 밸런스를 확인하세요 |
| 모터가 뜨거운가 | 손을 못 댈 정도면 프로펠러를 한 치수 줄입니다 |

## G. 화면이 깨진다

### 그래프 자리가 하얗게 비어 있다

**GCS v1.1 이전 버전의 버그입니다.** 고해상도(배율 1.25배 이상) 화면에서
캔버스 크기가 반복해서 곱해지며 폭주하던 문제로, v1.1.1에서 수정했습니다.

1. 최신 `gcs/index.html` 로 교체
2. <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd> 로 **강력 새로고침** (브라우저 캐시 때문에 꼭 필요합니다)

### 한글이 깨져 보인다

파일이 UTF-8로 저장되어 있는지 확인하세요.
메모장에서 열어 수정했다면 "UTF-8"로 다시 저장해야 합니다.

### 엑셀 파일이 안 열린다

- 파일 크기가 0이면 기록된 데이터가 없는 것입니다. `기록 시작` 을 먼저 누르세요
- 엑셀 대신 LibreOffice·구글 시트에서도 정상적으로 열립니다

## H. 빌드가 안 된다

### `ESPAsyncWebServer.h: No such file or directory`

라이브러리 매니저에 없는 라이브러리입니다. GitHub에서 ZIP으로 받아
**스케치 → 라이브러리 포함하기 → .ZIP 라이브러리 추가** 로 설치하세요.

- `ESPAsyncWebServer`
- `AsyncTCP` (이것도 함께 필요합니다)

### `Sketch too big` / 메모리 부족

도구 → Partition Scheme을 확인하세요.

| 보드 | 설정 |
|---|---|
| ESP32 NodeMCU | `Default 4MB with spiffs` |
| XIAO ESP32S3 | `Huge APP (3MB No OTA/1MB SPIFFS)` |

### 업로드 중 멈춘다 (`Connecting....____`)

보드의 **`BOOT` 버튼을 누른 채** 기다리세요. 업로드가 시작되면 떼면 됩니다.
그래도 안 되면 USB 케이블을 바꿔 보세요 — **충전 전용 케이블은 데이터가 통하지 않습니다.**

### 포트가 안 보인다

CH340 또는 CP2102 USB 드라이버를 설치해야 할 수 있습니다.
장치 관리자에서 느낌표가 뜨는 장치가 있는지 확인하세요.

---

## 그래도 해결이 안 되면

1. **문제를 반으로 쪼개세요.** 모터를 빼고 센서만, 센서를 빼고 통신만 — 어느 쪽에서 문제가 생기는지
2. **시뮬레이션과 비교하세요.** 시뮬레이션에서는 정상인데 실제에서만 이상하다면 하드웨어 문제입니다
3. **시리얼 모니터(115200)를 보세요.** 펌웨어가 부팅 과정과 오류를 모두 찍습니다
4. 그래도 안 되면 [Issues](../../issues)에 **시리얼 로그 · GCS 로그 · 배선 사진**을 함께 올려 주세요
